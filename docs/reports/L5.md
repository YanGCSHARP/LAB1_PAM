# Отчёт по лабораторной работе L5

**Дисциплина:** Программирование мобильных приложений (PAM), UTM / FCIM / ISA
**Тема:** T7 — WalletMate (личные финансы), уровень сложности «повышенный»
**Автор:** Yang Alexandru, группа `TI-236`
**Этап:** L5 — REST-интеграция с собственным backend-ом на шаблоне курса
**Дата:** ноябрь 2026

---

## 1. Цель этапа

Заменить mock-бэкенд L4 настоящим сервером. По заданию студент расширяет шаблон
курса сущностями своей темы, а JWT-аутентификация, CRUD, загрузка файлов,
пагинация и формат ошибок приходят из шаблона. Приложение должно работать с
сервером через те же интерфейсы репозиториев, что и на L4, не меняя экраны.

---

## 2. Что сделано

| Требование L5 | Реализация |
|---|---|
| Шаблон курса | .NET 9 Minimal API + SQLite (`backend/`), файлы шаблона не переписаны, только дополнены |
| Сущности темы | `Accounts.cs`, `Transactions.cs`, `Budgets.cs`, `Profile.cs` по образцу `Notes.cs`, таблицы в `Db.cs`, маршруты в `Program.cs` |
| JWT | из шаблона; на клиенте — `dio`-interceptor и токен в `flutter_secure_storage` |
| CRUD | 15 маршрутов WalletMate + профиль |
| Пагинация | `{items, page, limit, total}` шаблона; фильтры операций `type`, `category`, `accountId`, `from`, `to`, `search` |
| Загрузка файлов | `POST /files` шаблона → аватар профиля (`image_picker`) |
| Ошибки | `{"error": {"code", "message"}}`; клиент переводит их в `RepositoryException` |
| REST-клиент | `ApiClient` + 4 `Api*Repository` + `ApiAuthRepository` за интерфейсами L4 |

Демо-аккаунт `demo@walletmate.md` / `Demo1234` создаётся в пустой базе с теми
же данными, что показывал mock-бэкенд.

## 3. Backend

Что добавлено к шаблону:

| Файл | Что делает |
|---|---|
| `Db.cs` | таблицы `accounts`, `transactions`, `budgets`; поля профиля в `users`; `PRAGMA foreign_keys = ON` для каскада |
| `Errors.cs` | код `CONFLICT` (409) рядом с `EMAIL_TAKEN` шаблона |
| `Money.cs` | деньги в копейках, справочники валют, типов счёта и категорий |
| `Accounts.cs` | CRUD; `balance` считается SQL-запросом; уникальное название без учёта регистра |
| `Transactions.cs` | CRUD, фильтры и пагинация; владелец определяется через счёт |
| `Budgets.cs` | CRUD; `spentAmount` по валюте по умолчанию; один бюджет на категорию и месяц |
| `Profile.cs` | имя, валюта по умолчанию, аватар из загруженного файла |
| `Seed.cs` | демо-аккаунт относительно текущей даты |

Решения:

- **Копейки, а не `REAL`.** `0.7 + 0.1 + 0.1` в базе даёт ровно `0.9`.
- **Чужая запись — 404, а не 403.** Сервер не подтверждает, что запись с таким
  id существует у другого пользователя.
- **Уникальность названий сравнивается в C#.** `NOCASE` и `lower()` в SQLite
  сравнивают без регистра только латиницу, «наличные» и «Наличные» прошли бы.
- **Шаблон не ломается.** `/notes`, `/me`, `/files` работают как были.

## 4. Клиент

```
core/network/
├── api_config.dart     адрес API (--dart-define=API_URL), переключатель USE_MOCKS
├── api_client.dart     dio, JWT, перевод ошибок шаблона, постраничное чтение
└── token_storage.dart  flutter_secure_storage / память
features/*/data/api_*_repository.dart   REST-реализации интерфейсов L4
features/auth/application/auth_service.dart   вход, регистрация, восстановление и выход
```

| HTTP | Исключение в приложении |
|---|---|
| нет ответа | `NetworkException` «Нет связи с сервером…» |
| 400 | `ValidationException` с текстом сервера |
| 401 при входе | `UnauthorizedException` «Неверный email или пароль» |
| 401 с токеном | `UnauthorizedException` + выход из сессии |
| 404 / 409 | `NotFoundException` / `ConflictException` с текстом сервера |
| 5xx | `ServerException` |

- Реализацию выбирает одна строка на сущность: сервер по умолчанию, mock с
  `--dart-define=USE_MOCKS=true` и в тестах.
- Токен читается до первого кадра, поэтому повторный запуск открывает панель
  без экрана входа.
- Выход стирает токен и сбрасывает загруженные данные (ограничение L4 снято).
- Android: разрешение `INTERNET` и `usesCleartextTraffic` для HTTP; iOS:
  `NSAllowsLocalNetworking` и описание доступа к фото.

## 5. Проверка

```
$ cd backend/Tests && dotnet test
Пройден! не пройдено 0, пройдено 33

$ cd app && flutter analyze
No issues found!

$ cd app && flutter test
00:16 +198: All tests passed!
```

Backend: авторизация и формат ошибок шаблона, изоляция пользователей, каскадное
удаление, деньги без погрешности, фильтры и пагинация, бюджеты по валюте,
аватар. Клиент: `ApiClient` и REST-репозитории на поддельном HTTP-адаптере,
вход, регистрация, выход и восстановление сессии; 172 теста L2–L4 работают на
mock-бэкенде без изменений. Вручную: web-сборка против запущенного сервера —
вход демо-аккаунтом, загрузка данных постранично, восстановление сессии после
перезагрузки.

## 6. Ограничения и что дальше

| Ограничение | Когда снимается |
|---|---|
| Без сети приложение показывает ошибку и «Повторить» | L6: локальная БД и очередь синхронизации |
| Агрегаты панели считает клиент, хотя сервер отдаёт `balance` и `spentAmount` | L6 или по требованию |
| Список операций читается целиком страницами по 100 | достаточно для личных финансов; бесконечная прокрутка — по необходимости |
| HTTP без TLS, открытый CORS, секрет JWT по умолчанию | настройки шаблона для лабораторной; в release задаётся `JWT_SECRET` |
