# Защита проекта WalletMate

Шпаргалка на 7–10 минут: что показать, в каком порядке и что ответить на
типичные вопросы.

---

## 1. Подготовка (до защиты)

```bash
cd backend
dotnet run                      # http://localhost:8080, демо-аккаунт в пустой базе
```

```bash
cd app
flutter run                     # эмулятор Android ходит на 10.0.2.2:8080 сам
```

- Демо-аккаунт: **`demo@walletmate.md` / `Demo1234`**.
- Чтобы начать с чистыми данными, удалить `backend/app.db` и перезапустить сервер.
- Запасной вариант без сервера: `flutter run --dart-define=USE_MOCKS=true`.
- Release APK заранее: `flutter build apk --release --split-per-abi --obfuscate --split-debug-info=build/symbols`.

## 3. Архитектура в двух словах

```
экраны (presentation) → провайдеры Riverpod (application) → интерфейсы репозиториев (data)
    → Cached*Repository → Api*Repository → ApiClient (dio + JWT) → backend на шаблоне курса
                         ↘ Mock*Repository (USE_MOCKS, тесты)
```

- **Слои внутри каждой функции:** `domain` (модели и расчёты), `data`
  (репозитории), `application` (провайдеры), `presentation` (экраны).
- **Одна строка выбирает реализацию** репозитория: mock на L4 заменился REST на
  L5 без правок экранов.
- **Backend** — шаблон курса (.NET 9 Minimal API, SQLite, JWT, ошибки, файлы,
  пагинация) + `Accounts.cs`, `Transactions.cs`, `Budgets.cs`, `Profile.cs` по
  образцу `Notes.cs`.

## 4. Вопросы и ответы

**Почему Riverpod?** Производные значения (баланс, сводка месяца, прогресс
бюджетов) — это провайдеры поверх источников: изменили операцию — Riverpod сам
пересчитал всё зависимое. Меньше шаблонного кода, чем у Bloc, и нет кодогенерации.

**Как устроен JWT?** Сервер (шаблон) подписывает HS256: `header.payload.signature`,
в `sub` — id пользователя, срок — 7 дней. Клиент кладёт токен в
`flutter_secure_storage` и добавляет `Authorization: Bearer` в interceptor `dio`.
401 на запросе с токеном завершает сессию.

**Где хранится пароль?** Нигде в открытом виде: PBKDF2-HMAC-SHA256, 100 000
итераций, случайная соль, формат `итерации:соль:хэш`.

**Почему деньги в копейках?** `0.1 + 0.2 ≠ 0.3` в `double`. Сервер хранит
`INTEGER`-копейки, клиент считает суммы через класс `Money` в целых копейках —
бюджет на ровно 90 % не превращается в 89,99 %.

**Почему баланс не хранится?** Одна операция не может «забыть» обновить
баланс: он всегда `начальный + доходы − расходы`.

**Что если запросить чужой счёт?** 404, как для несуществующего: сервер не
подтверждает, что такой id есть. Все запросы фильтруются по `user_id` из токена;
это проверяет интеграционный тест.

**Как работает пагинация?** Формат шаблона `{items, page, limit, total}`,
`limit` до 100. Приложению для расчётов нужны все операции, поэтому оно читает
страницы по 100 до `total`.

**Что будет без интернета?** Последняя загруженная копия сохранена в
`shared_preferences`, репозиторий отдаёт её при `NetworkException`, сверху
плашка. Изменения без сети не принимаются — так нет конфликтов при
синхронизации.

**Почему не очередь офлайн-изменений?** Для личных финансов цена ошибки
синхронизации (двойная операция) выше пользы от записи без сети. Копия на
чтение закрывает главный сценарий — посмотреть баланс и бюджет без связи.

**Что делает release-сборка?** Подпись своим ключом из `key.properties`,
обфускация Dart-кода, символы отдельно в `build/symbols`, сборка по ABI.

**Как тестировали?** Unit-тесты расчётов и порогов, моделей, репозиториев,
провайдеров, сетевого слоя на поддельном HTTP; widget-тесты экранов,
навигации, вёрстки на 360 px; 33 интеграционных теста сервера. Итого 201 тест
приложения и 33 — backend-а.

**Что отличается от плана L1?** Backend сделан на шаблоне курса вместо
ASP.NET Core + EF Core (так требует L5); вместо локальной БД `drift` с очередью
— копия данных на чтение.
